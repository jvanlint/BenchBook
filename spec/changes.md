# Changes since BenchBook 1.0

What the Mac app has gained since 1.0, newest first, so the Windows app can
catch up. Each entry says where the spec describes it. When a Windows change
brings one across, note it in the Windows project, not here.

The spec sections are the reference. This list is only a checklist.

| Change | Issue | Format change | Spec |
|---|---|---|---|
| Four more paint types: Acrylic Wash, Enamel Wash, Pigment and Marker, before Other in the menus. Older versions show them as Not Set and keep them. | – | No | behaviour.md › Paint types |
| Safety: link previews stop reading at size limits and fetch redirects, preview images, icons and posters only from public web addresses. The capture inbox ignores links. Restore checks that manifest paths stay inside the backup. | #15 | No | behaviour.md › Webpages, Browser extension; library-format.md › Restoring a backup |
| A PDF markup's number badge is kept wholly on the page: one starting at the page edge is drawn moved inward instead of cut in half, in the viewer and in export. | #39 | No | behaviour.md › PDF markups |
| A project holds each link once: saving a webpage or video link with exactly the same address as one already in the project reports it as already saved. A file saved with the page it came from (such as an image from Safari) keeps that page as its source. | #7 | No | behaviour.md › Capture |
| A Safari extension saves pages, images, PDFs and highlighted text from the right-click menu or toolbar, shows the outcome in the page, and can move a save to another project. Windows plans an Edge and Chrome extension, which should work the same way. | #7 | No | behaviour.md › Browser extension; screens.md › Safari extension |
| Custom mixes: a paint made from other catalogue paints, with a recipe of parts. A mix counts as owned when every recipe paint is; a project using it puts the missing paints on the Shopping List "for" the mix. Paints in a recipe can't be deleted. Add Mix on the Paints screen. A project's Paint tab gains a Notes column. Mixes aren't in the paint CSV. | #42 | Yes: schema 6.0.0, `paints.isMix`, `paintMixParts` | library-format.md › paints, paintMixParts, Compatibility; behaviour.md › Paint identity, Mixes, Deleting, Shopping list, Paint CSV › Export; screens.md › Paint tab, Paints catalogue, Paint editor |
| Paint standards are a system (FS 595, RAL, RLM, BS 381C and more, Multiple or Custom) and a code, for paints and for colours in a project's painting guide. Paints gain Match (No, Closest or Exact Match) and Type (water-based acrylic, lacquer and so on), with a Type filter on the Paints screen and in the paint picker. The paint picker lists paints with the colour's standard first. The CSV gains Standard, Standard Code, Match and Type columns in place of FS/RLM. The upgrade splits the old text, keeping anything it doesn't recognise. | #42 | Yes: schema 5.0.0, `paints.standardSystem`, `paints.match`, `paints.type`, `projectPaints.standardSystem` | library-format.md › paints, projectPaints, Compatibility; behaviour.md › Paint search, Paint standards, Reading standard text, Paint types, Filters, Upgrading from schema 4, Paint CSV; screens.md › Paint tab, Paint picker, Paints catalogue, Paint editor |
| Clear paints (any paint with "clear" in its name) are drawn as glass, not flat white or colour. | #42 | No | behaviour.md › Swatches; screens.md › Paint editor |
| Projects use kits from the catalogue: a Kits tab in each project (⌘1, so the other tabs move to ⌘2–⌘5), kits chosen in the new-project sheet, Move to Project, status following the project, needed kits on the Shopping List, and a Project column and Not in a Project and Needed filters on the Kits screen. Project manufacturer, scale and kit number are removed; the upgrade adds them to the notes. The library is copied before an upgrade. | #44 | Yes: schema 4.0.0, `kits.projectId`; `projects.manufacturer`, `scale` and `kitNumber` removed | library-format.md › projects, kits, The library on disk, Compatibility; behaviour.md › Kits in projects, Upgrading from schema 3, Shopping list, Deleting; screens.md › Project Kits tab, Project editor, Kits catalogue, Shopping list |
| Kits catalogue: one entry per physical kit, with status, rating, prices, box art, Scalemates and BenchBook CSV import and export, and search. | #41 | Yes: schema 3.0.0, `kits`, and the `decimal` value type | library-format.md › kits; behaviour.md › Kits; screens.md › Kits catalogue, Kit editor |
| The aftermarket editor's picture well is shared with the kit editor. No change for the user. | #41 | No | screens.md › Aftermarket editor |
| Sort projects in the sidebar by Name, Date Created or Last Updated. The choice is remembered. | – | No | behaviour.md › Sorting; screens.md › Sidebar |
| A project's last updated date now changes whenever the user changes anything in the project, not only its details. | – | No, but the rule is **(stored)** | behaviour.md › When a project was last updated |
| Build Photos: the user's own photos of a build, with WIP and Completed stages, notes, tags, box notes, a project photo in the header, and export without location data. | #43 | Yes: schema 2.0.0, `buildPhotos`, `buildPhotoTags`, `projects.projectPhotoId`, `markups.buildPhotoId` | library-format.md; behaviour.md › Build photos; screens.md › Build Photos |
| Build Photos: select by dragging a rectangle, as in References. Delete works on a rectangle selection. | #43 | No | screens.md › Build Photos |
